# RFC 2136 / TSIG backend (pre-alpha)

The adapter in `src/universalddns/adapters/rfc2136.py` implements the existing
`DNSBackend.publish(rrset)` port for A and AAAA RRsets. It uses `dnspython`
and TCP with TSIG authentication (HMAC-SHA256/384/512).

## Configuration

Construct `RFC2136Config(zone, server, key_name, key_secret, ...)`.
The server must be an IP address, and the TSIG secret is base64 encoded.
Never commit actual secrets to Git or expose them through an HTTP API.

The adapter performs a **complete RRset replacement**, not an append. The
authoritative server MUST restrict the TSIG key to precisely authorized zones,
names and record types. The client-side zone check alone is not sufficient.

## Limitations and verification

- Only A and AAAA updates; no deletes, CAS/prerequisites or DNSSEC management.
- A successful DNS UPDATE response does not prove propagation, resolver cache
  expiration, endpoint availability, or consistency among authoritative replicas.
- Transport errors may have ambiguous outcomes. Reconcile before retrying.
- Unit tests simulate network responses and inspect constructed DNS UPDATE
  messages. A real isolated authoritative-server integration test is still needed.
- The process must not expose secrets through logs or exception responses.
- The adapter is not yet wired to a production worker or operator configuration.

Run: `python -m unittest discover -s tests -v`
