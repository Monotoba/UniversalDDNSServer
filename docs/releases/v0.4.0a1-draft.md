# UniversalDDNSServer v0.4.0a1 — Draft release notes

**Status: release candidate documentation only.** No v0.4.0a1 tag, prerelease, or artifact is asserted to exist. Current `main` remains development software, and `pyproject.toml` still identifies version `0.3.0a1`. Do not publish until version, checks, installed-VM validation and owner approval are complete.

## Changes since v0.3.0a1

- SQLite-backed operator-managed A/AAAA catalog: create, revise and stage records active/inactive using revision checks; dynamic records become visible to scoped REST consumers only when active.
- REST `GET /api/v1/records` discovery for authorized records and `PUT /api/v1/records/{id}/address` for catalog-backed updates queued to the independent worker.
- Active-record authorization rechecked during publication; deactivation prevents newly authorized updates and prevents most queued publication, but cannot cancel a DNS write already in flight.
- Token issuance for active catalog records via a local-only operator CLI. Deactivation does not globally disrupt unrelated tokens. Reactivation requires revoking all existing nonrevoked credentials that grant the record ID, preventing automatic authority restoration.
- Credential inventory and reactivation blocker reporting, with database-local `cred-N` references; authorized operators can revoke by reference without original bearer tokens.
- Durable, transactionally recorded SQLite credential issuance/revocation events and nonsecret event history. CLI credential mutations capture verified local OS operator identity; historical or lower-level mutations may have an unknown actor.
- Expanded unit, integration, operator and upgrade documentation, including experimental VM fixture-bootstrap compatibility with the new local identity rules.

The DynDNS2 compatibility endpoint from v0.3 is retained and remains limited to statically configured record mappings; the new catalog is not exposed through it.

## Compatibility and migration

- Python 3.11+; CI uses 3.11, 3.12 and 3.13 with isolated BIND 9.
- Existing token and catalog SQLite tables are migrated additively where needed; the credential audit adds a nullable operator column. Back up the complete SQLite state using its backup API before upgrade.
- Local credential CLI `issue`, `revoke` and `revoke-reference` require a non-root POSIX operator with matching UID/EUID and membership in `universalddns-operators`. Operators need separately provisioned secure read/config and write/database permissions. The earlier `sudo -u universalddns` administration pattern is not valid for these commands.
- Records must be staged active before local token issuance. Nonrevoked old grants block inactive-to-active transitions, including initial activation with legacy grants.
- Use the guarded disposable-VM updater and [v0.4 operator instructions](../operations/V0_4_LOCAL_OPERATOR_UPGRADE.md); no unattended production migration is supported.

## Security and operational limitations

- Pre-alpha, loopback-only HTTP: **never expose directly to public networks**. No supported production TLS ingress or distributed rate limiter.
- Does not include a first-party authoritative DNS server. Requires external RFC 2136/TSIG DNS with tightly scoped permissions.
- HTTP 202 queues work; it does not prove authoritative DNS changed. Ambiguous external writes require observation/reconciliation; in-flight DNS requests cannot be fully fenced by credential revocation/deactivation.
- `cred-N` selectors are SQLite row identifiers, not durable portable credential IDs. Reinspect inventory after rebuild, import, or database maintenance.
- Credential history is not tamper-evident; older rows and internal calls can lack verified actor attribution.
- The VM fixture's DNS-writing update test validates a **static** record only. Installed-VM catalog/revocation/operator operations have not been fully demonstrated by that test.
- Full in-flight crash/transport-failure recovery, general multi-writer correctness, high availability and production disaster recovery are unverified.
- No public administrative API for records or tokens.
