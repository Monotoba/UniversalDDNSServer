# UniversalDDNSServer v0.2.0a1 — Alpha release notes

**Status:** Published GitHub alpha prerelease on 2026-10-14, tagged `v0.2.0a1` at commit `9e6c7801b69cec458bab539e1e3d34f5fb3eaf70`. This alpha is for an isolated, loopback-only test environment, not internet-facing or production deployments.

## Changes since v0.1.0a1

- Operator intent inspection and observation-only reconciliation, with distinct exit statuses for unresolved, refused, missing, and unreachable operations.
- Structured, redacted JSON audit events for API authorization, updates, worker publications, and recovery outcomes; journald is the logging sink, not a tamper-resistant audit database.
- Local API-token metadata inventory and documented staged replacement/revocation procedure. Token material and digests are omitted from inventory.
- VM updater with a SQLite backup, API readiness checks, non-mutating verification, and **best-effort** rollback.
- Additional unit coverage for reconciliation statuses, withheld retries, token revocation and inventory safety.

## Install and compatibility

- Python 3.11+; Linux local test deployment demonstrated on Ubuntu 24.04.
- API binds to `127.0.0.1:8765` by default in the provided service. No TLS/public ingress is supplied.
- BIND 9 is a separately configured authoritative DNS service using restricted RFC 2136 TSIG credentials.
- Upgrade the experimental VM using `bash ~/update-vm.sh`; it backs up state and verifies services. Preserve the backup and review upgrade logs. The package version will be `0.2.0a1` after reinstalling this revision.

## Important limitations

- A queued update is not proof of DNS publication. Server reply loss can make writes ambiguous; do not blindly retry.
- Reconciliation assumes no independent concurrent writer changes the managed record set. There are no exactly-once DNS guarantees.
- Local process rate limiting is not distributed. Credentials must be protected on disk. A revoked token does not cancel an in-flight update; another valid scoped token for the same principal may preserve authorization.
- Rollback is best effort, not transactional across code, database, DNS and in-flight operations. Crash recovery and disaster recovery are not production certified.
- Journald retention is configured at the host level; logs are not tamper-resistant.
- No bundled authoritative DNS server, high availability, general multi-writer CAS, or internet-ready security layer.
