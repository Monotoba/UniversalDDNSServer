# Contributing

Contributions, testing, protocol interoperability reports and documentation fixes are welcome.

1. Open an issue for substantive API, schema, security or architecture changes.
2. Keep core modules independent of specific DNS providers and databases.
3. Include positive, negative, and edge-case automated tests with every behavior change.
4. Update API/interface docs, changelog and migration notes whenever public behavior changes.
5. Never commit tokens, keys, domain credentials, private logs or user data.
6. Keep PRs focused, explain rationale, list test commands and link issues.

Use clear commit messages such as `feat(api): validate IP update requests`. A DCO is not imposed at this stage. Contributors should ensure they have the right to submit BSD-2-Clause-compatible contributions.
